# CoffeeProd 2차 개선: 혼합 부하 지연 진단

- 상태: 2026-10-12 합의한 진단 범위 종료. 혼합 경로·터널/타이밍·패킷·공유/단독·SSH 클라이언트 비교를 완료했습니다. 정확한 근본 원인과 2차 Backend 개선 성공은 미확인입니다.
- 목표: 동일 혼합 부하에서 공개 HTTPS와 SSH 원본 경로의 클라이언트 지연·서버 처리 지표를 분리합니다.
- 1차 사례: [주문 인덱스 개선](../1차개선/README.md). 원본 A3와 후속 예열 실패는 변경하지 않습니다.

## 고정한 진단 계획

기존 `k6/scripts/baseline.js`와 입력을 그대로 사용합니다. 공개 15·회원 4·로그인 1 iteration/s, 원본→공개 순서, 경로별 예열 2분·본 측정 5분, 단계 간 휴지 90초입니다. 경로별 본 측정은 1회로 고정하며 좋은 결과가 나올 때까지 반복하지 않습니다. 약 19~20분입니다.

기존 임계값을 바꾸지 않습니다. 이번은 성능 인수가 아닌 원인 진단이므로 지연 임계값 초과(exit 99)만 있는 경우 그 실패를 보존하고 다음 계획 단계의 수집을 계속합니다. HTTP·업무·인증·check 오류나 dropped iteration, 연결·scrape·입력 가드 실패는 즉시 중단합니다. 지연 실패를 PASS로 바꾸지 않습니다.

주문·결제·재고·마일리지 쓰기는 제외합니다. 기존 조회성 추천 POST와 로그인에 따른 인증 상태 변경은 포함됩니다. 서버·DB·R2·Frontend 및 애플리케이션 코드는 변경하지 않습니다.

## 관측과 한계

클라이언트 raw timing, 엔드포인트별 분위수·느린 요청 수, 서버 URI별 histogram·CPU·GC·HikariCP 대기, Windows CPU·메모리 표본을 저장합니다. 원본은 SSH/HTTP1.1, 공개는 TLS/HTTP2 등 전달 조건이 달라 차이를 순수 Cloudflare 비용으로 해석하지 않습니다.

사용자는 시험 중 Ubuntu 배포·설정·데이터를 변경하지 않는다고 확인했습니다. 수동 상태 출력을 반복 요청하지 않습니다. 무인 SSH 인증을 통한 apt 조회는 인증 실패로 불가능했으므로 최신 유지보수·VM 호스트 상태는 미확인으로 기록합니다. 로컬 health·target freshness는 자동 감시합니다. 자동 업데이트나 VM 호스트 변경 가능성이 배제된 것은 아닙니다.

순서를 교차하지 않는 한 쌍의 진단이며 endpoint 선택은 무작위입니다. 양쪽 latency 차이는 원인 후보를 좁히는 근거이지 인과관계·안정적 p99·최대 처리량 증명이 아닙니다. 원인이 확인되면 필요한 DEV 업무를 별도로 할당하고 개선 후 반복 검증합니다.
