## 비교 조건

Windows의 OpenSSH 9.5p2/LibreSSL 3.8.2와 Git의 OpenSSH 10.3p1/OpenSSL 3.5.6을 비교했습니다. 둘 다 OpenSSH이며 서로 완전히 다른 프로토콜 구현을 비교한 것은 아닙니다. 버전·빌드·암호화 런타임이 함께 달라 개별 요소의 영향을 분리할 수 없습니다.

18081은 Windows, 18082는 Git의 API 전용 forwarding입니다. 각 프로세스의 실행 파일·바이너리 SHA-256·단일 forwarding·서버 SSH 연결을 확인했고, 모니터링은 별도 공유 프로세스에 유지했습니다. HTTP/1.1·연결 재사용·동일 헤더·동일 응답 data digest를 사용했습니다.

1 VU, 구간마다 15건, 시작 간격 최소 1초입니다. Windows→Git / Git→Windows를 네 블록으로 교차해 각 60건을 측정했습니다. 최초 요청도 포함하며 새 k6 구간마다 HTTP 연결은 다시 만들어집니다. 별도 예열·결과 선택·좋은 결과를 위한 재측정은 없습니다.

8구간 모두 exit 0, HTTP 120/120·업무 check 120/120 성공입니다. 입력 20개 hash·응답 digest·실제 요청 URL·프로토콜·native 7종 timing·구간별 p95/p99를 검증했습니다. health/freshness 관측 17개 모두 통과했고 보수적 sample age 최대 15.00초로 기존 45초 기준 이내였습니다.

## 지연 구간의 차이

| native timing, 각 60건 | Windows 중앙값 | Git 중앙값 |
|---|---:|---:|
| 첫 응답 대기 `http_req_waiting` | 44.01ms | 7.47ms |
| 본문 수신 `http_req_receiving` | 0.00ms | 46.60ms |

전체 응답 교환 시간 합계 중 Windows는 waiting이 95.81%, Git은 receiving이 84.80%였습니다. 분위수끼리 합산한 값이 아니라 각 timing 합계/전체 duration 합계입니다. 수신 0.00ms는 계측 표시값이며 실제 전송 시간이 물리적으로 0이라는 뜻은 아닙니다.

**첫 바이트만 보면 Git이 빠르지만 전체 응답 완료는 더 느렸습니다.** 전달·버퍼링·TCP 처리/계측 구간의 차이가 남아 있다는 관측입니다. 암호화 채널의 요청별 패킷 대조나 OS scheduling trace는 없어 ACK/Nagle·특정 SSH 버그를 확정하지 않습니다.

같은 실행 창의 서버 표본 10개에서 카테고리 rolling 1분 p99는 8.35~11.95ms, 앱 `process_cpu_usage` 최대 1.806%, HikariCP pending은 0이었습니다. 15초 간격 표본이며 VM 전체 자원·순간 peak·요청별 span이 아닙니다. 서버 p99와 클라이언트 중앙값을 빼서 네트워크 비용을 계산하지 않습니다.

## 최종 판단과 남은 과제

1. **확인됨:** 저빈도 카테고리 조회에서 두 단독 SSH 경로 모두 수십 ms가 남습니다. Git 클라이언트 교체로 이를 제거하지 못했습니다. 공유 모니터링이나 Windows OpenSSH 한 빌드만의 문제라는 설명은 충분하지 않습니다.
2. **유력 후보:** SSH forwarding·클라이언트·TCP/VM 전달 구간입니다. 전체 혼합 부하의 로그인 tail과 과거 A3 지연까지 같은 원인으로 확정하지 않습니다.
3. **이번 범위 종료:** 자동으로 추가 캡처·부하·설정 튜닝을 이어가지 않습니다. 특정 Backend 코드 병목을 확인하지 못했으므로 DB/BCrypt/메모리 튜닝 DEV 업무를 임의 할당하지 않습니다.
4. **별도 과제:** 근본 원인 확정이 필요하면 요청별 span과 클라이언트/서버 OS·VM scheduling/TCP trace를 별도 인프라 조사로 계획합니다. 공개 서비스 개선 인수·최대 처리량·안정적 p99 검증은 이번 저빈도 비교의 범위 밖입니다.

1차 주문 인덱스 개선의 증빙은 유지합니다. 2차 기록은 '측정 경로를 분리해 원인 후보를 좁힌 진단'이며 새 Backend 개선 성공 사례로 표현하지 않습니다.
