## 2. AI 추천 정책

### 모델과 입력·결과

| 항목 | 초기 정책 |
|---|---|
| 제공사·모델 | Gemini Developer API / `gemini-4-hydrogen` |
| 이용 대상 | 로그인한 활성 회원. 비회원의 기존 선택형 추천 유지 |
| 입력 전체 | 시스템 지시·취향·후보 정보를 포함해 6,000토큰 이하 |
| 출력 | 추론을 포함해 2,048토큰 이하, 추론 수준 `low` |
| 후보·결과 | 판매 중·재고 보유 내부 상품 최대 20개 / 추천 최대 5개 |
| 시간 제한 | 외부 요청 전체 15초 |
| 재시도·도구 | 자동 재시도 없음. 외부 검색·웹 탐색 등 도구 사용 안 함 |

서버가 기존 상품·취향 정보를 바탕으로 후보를 구성하고 상한을 넘으면 후보 설명을 줄여 입력 한도를 지킨다. 모델에는 필요한 상품 정보와 취향만 보내며 회원·주문 개인정보는 전송하지 않는다. 사용자 입력과 상품 설명을 시스템 명령으로 취급하지 않는다.

응답 상품 ID는 전달한 후보와 최신 판매 상태에 대조한다. 가격·상품명·재고·상세 링크는 DB에서 구성하고, 없는 상품·외부 상품·품절·판매 중지 상품이나 근거 없는 설명은 표시하지 않는다. 잘못된 응답, 출력 상한으로 끝난 불완전 응답, 빈 결과·시간 초과·제공사 장애·한도 초과는 적절히 안내하고 기존 추천 이용 경로를 제공한다.

초기 모델은 공식 모델·기능 문서에 따라 선정했다. 한국어 취향 이해·추천 이유·응답 시간의 실제 품질은 DEV·QA에서 검증한다. [모델 안내](https://ai.google.dev/gemini-api/docs/models/gemini-4-hydrogen), [추론 및 출력 제한](https://ai.google.dev/gemini-api/docs/thinking#token-limits)

### 이용·비용 제한

| 범위 | 한도 |
|---|---|
| 회원별 호출 | 분당 2회 / 하루 20회 |
| 서비스 전체 호출 | 하루 100회 |
| 앱 AI 예산 | 월 $8 |
| 제공사 프로젝트 | 설정 가능한 경우 월 $10 |
| 집계 기준 | 일·월은 UTC. 분당 제한은 연속 요청으로 우회하지 못하게 관리 |

호출 전에 최대 예상 비용을 원자적으로 예약하고 실제 사용량으로 정산한다. 동시에 요청해도 잔여 예산을 중복 사용하지 못하게 한다. 과금 여부를 알 수 없는 실패·시간 초과는 예약액을 보수적으로 유지하고 확인 전에는 예산으로 돌려주지 않는다. 비용 상태나 제한 저장소를 확인할 수 없으면 새 AI 호출을 중단하고 기존 추천을 안내한다.

공식 표준 단가는 입력 100만 토큰당 $1.50, 추론 포함 출력 $7.50이다. 외부 도구·명시적 캐시 등 추가 기능을 사용하지 않는 이 정책의 예시는 다음과 같다.

| 조건 | 계산 | 예상 API 사용료 |
|---|---|---|
| 입력 3,000 + 추론 포함 출력 1,000토큰 | 3,000 × 1.50 / 1,000,000 + 1,000 × 7.50 / 1,000,000 | 요청당 $0.012 / 100회 $1.20 |
| 입력 6,000 + 추론 포함 출력 2,048토큰 | 6,000 × 1.50 / 1,000,000 + 2,048 × 7.50 / 1,000,000 | 요청당 최대 예상 $0.02436 |
| 위 상한을 모두 사용하는 경우 | $8 ÷ $0.02436 | 월 328회, 잔여 $0.00992 |

예시는 할인·캐시 절감·세금·환율을 적용하지 않은 계획용 계산이다. 실제 과금은 제공사 사용량·청구 기준을 따른다. 단가가 변경되거나 모델을 교체하면 예약 비용 계산과 한도를 함께 재검증한다. 월 328회는 모든 요청이 상한에 도달하는 가정이며 호출 횟수 보장이나 처리량 측정값이 아니다. [공식 요금표](https://ai.google.dev/gemini-api/docs/pricing#gemini-4-hydrogen)

가능하면 전용 Google 프로젝트와 API 키로 다른 서비스의 사용량을 분리한다. 프로젝트 한도는 제공 여부와 권한을 확인한 뒤 $10으로 설정한다. 공식 비용 제한은 집계 지연 등에 따라 초과할 수 있으므로 앱의 $8 예약·차단을 함께 적용한다. 한도 도달 시 고가 모델이나 다른 제공사로 자동 전환하지 않는다. [Google 프로젝트 비용 제한](https://ai.google.dev/gemini-api/docs/billing#project-spend-caps)

## 3. 인증 메일 정책

### 발송 서비스와 도메인

- Resend Free를 사용한다. 공식 제공량은 월 3,000건·일 100건이다.
- 앱은 가입 보완 인증과 비밀번호 복구를 합쳐 일 80건·월 2,400건으로 제한한다. UTC 일·월로 집계하며, 제공사 자체 집계 주기와 잔여량 제한도 함께 따른다.
- 발신 도메인: `mailsender.ttagyulab.com`
- 발신 주소: `CoffeeProd <no-reply@mailsender.ttagyulab.com>`
- 별도 도메인 구매 없이 기존 `ttagyulab.com`의 DNS에 Resend가 표시하는 실제 인증 레코드를 추가한다. 서브도메인은 웹사이트를 새로 띄우거나 수신함을 만드는 작업과 구분한다.
- 사용자는 Resend 도메인 화면의 DKIM·SPF·발송용 MX 등 요구 레코드를 DNS에 추가한다. QA_DEVOPS는 인증 상태와 실제 발송·수신을 확인한다. 안내 문서의 예시 레코드 값을 그대로 복사하지 않는다.
- 기존 웹사이트와 수신 메일의 DNS·MX는 보존한다. 수신 기능·열람 및 클릭 추적·유료 요금제·초과 과금 옵션은 이번 인증 메일 범위에 포함하지 않는다.

[Resend 요금표](https://resend.com/pricing), [도메인·서브도메인 안내](https://resend.com/docs/dashboard/domains/introduction), [Cloudflare DNS 설정 안내](https://resend.com/docs/guides/dns/cloudflare)

### 인증번호와 재설정 권한

| 항목 | 초기 정책 |
|---|---|
| 인증번호 | 암호학적 난수 6자리, 앞자리 0 포함 |
| 코드 유효시간 | 발급 후 5분 |
| 재발송 | 최소 60초 간격, 재발송 성공 시 이전 코드 무효화 |
| 코드별 검증 실패 | 최대 5회 |
| 이메일별 누적 검증 실패 | 15분당 10회. 재발송으로 초기화하지 않음 |
| 이메일별 발송 | 시간당 3회 / 하루 5회 |
| IP별 발송 | 시간당 10회 / 하루 20회 |
| 비밀번호 재설정 권한 | 인증 성공 후 5분, 일회성, 해당 사용자·목적에만 사용 |

인증번호·권한은 안전하게 보관하고 성공·실패 횟수·만료·소비 처리를 동시 요청에서도 일관되게 적용한다. 시간당·15분당 제한은 연속 요청으로 우회하지 못하도록 관리한다. 제한은 계정 로그인 자체를 잠그는 용도로 사용하지 않는다.

`PASSWORD_RESET`과 `OAUTH_SIGNUP_EMAIL`은 공통 인증 컴포넌트를 사용하되 별도 목적으로 구분한다. 같은 코드를 다른 목적·이메일·가입 거래에 재사용할 수 없다. 비밀번호 재설정용 메일은 가입 이메일에만 보내며 초기 요청 응답으로 가입 여부를 노출하지 않는다. 가입 보완은 제공사 인증을 마친 가입 대기 거래의 이메일에만 수행한다.

소셜 전용 계정에 복구 API로 로컬 비밀번호를 추가하지 않는다. 비밀번호 재설정 성공 시 기존 AccessToken·RefreshToken을 무효화하고 재로그인을 요구한다. 메일 발송 실패 시 존재하지 않는 유효 코드를 남기거나 이전 유효 코드를 먼저 폐기하지 않는다. 발송 요청의 일시적 실패·결과 불명 처리와 실제 발송 여부는 DEV·QA에서 검증한다.

위 수치는 이 프로젝트의 초기 운영 정책이다. 인증번호·재설정 권한을 로그·검증 증거에 남기지 않으며, 실제 수신과 정책 검증은 별도로 기록한다. [비밀번호 복구 설계 참고](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)

## 4. OAuth 가입·로그인 정책

### 제공 정보와 계정 연결

- Google 요청 범위: `openid email profile`. Google Cloud 계정·Gemini API 키와 웹 OAuth 클라이언트 자격 증명은 별도로 준비한다.
- 카카오: 일반 로그인 활성화와 닉네임 제공을 우선 설정하고 REST API 키·클라이언트 시크릿·이메일 동의 항목의 권한을 확인한다. 이메일이 항상 제공된다고 가정하지 않는다.
- Google ID 토큰의 서명·발급자·대상·만료와 검증 상태, 카카오 사용자 식별자·이메일 유효 및 인증 상태 등을 제공사 문서에 따라 검증한다.
- 신규 가입의 이름·닉네임을 보완하고 이메일이 없거나 검증되지 않았다면 직접 입력 후 `OAUTH_SIGNUP_EMAIL` 인증을 수행한다. 이메일 변경 입력도 검증 없이 신뢰하지 않는다.
- 제공사와 제공사 사용자 식별자로 계정을 구분한다. 기존 이메일과 겹치면 자동 병합하지 않고 기존 계정 본인 확인 후 연결한다. 정지·탈퇴 정책을 우회하지 못하게 한다.
- 소셜 전용 계정도 로컬 비밀번호 없이 회원 탈퇴 등 필요한 본인 확인을 수행할 수 있게 한다.

[Google OIDC](https://developers.google.com/identity/openid-connect/openid-connect), [카카오 제공 정보·동의 항목](https://developers.kakao.com/docs/ko/kakaologin/utilize), [카카오 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api)

### 환경별 등록 주소

| 환경 | 제공사 | 제공사에 등록할 전체 콜백 URL |
|---|---|---|
| 로컬 | Google | `http://localhost:8080/login/oauth2/code/google` |
| 로컬 | 카카오 | `http://localhost:8080/login/oauth2/code/kakao` |
| 운영 | Google | `https://api-coffeeprod.ttagyulab.com/login/oauth2/code/google` |

| 환경 | 백엔드 기준 주소 | 프론트 기준 주소 | 처리 후 프론트 경로 |
|---|---|---|---|
| 로컬 | `http://localhost:8080` | `http://localhost:3000` | `/auth/callback` |
| 운영 | `https://api-coffeeprod.ttagyulab.com` | `https://coffeeprod.ttagyulab.com` | `/auth/callback` |

이는 신규 기능에 적용할 등록 계약이다. 현재 해당 경로가 구현됐거나 제공사 콘솔에 등록됐다고 표시하지 않는다. `127.0.0.1`·다른 포트·미리보기 도메인은 위 등록 주소에 포함하지 않는다. 필요 시 새 주소를 명시적으로 등록·검증한다.

인가 코드 처리는 백엔드에서 수행한다. 서비스 토큰과 제공사 토큰은 URL에 넣지 않는다. 콜백 이후 인증 취소·추가 가입·기존 계정 연결을 구분하고, 인증 요청 위조·재사용·임의 리다이렉트를 방지한다. JWT 전달·교환 방식의 구체적 API 계약은 DEV-OAUTH-001에서 기존 프론트 인증 흐름과 함께 확정·검증한다.

앱 이름·서비스 주소·지원 연락처·요청 범위·동의 화면과 테스트/공개 이용 가능 상태도 확인한다. 카카오싱크 등 추가 기능은 이번 기본 로그인에 필수라고 가정하지 않는다. [카카오 로그인 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite), [Google 웹 OAuth 설정](https://developers.google.com/identity/protocols/oauth2/web-server)

## 5. 제공사 교체와 공통 계약

| 영역 | 공통 경계 | 교체 범위 | 반드시 재검증할 항목 |
|---|---|---|---|
| AI | 후보 상품·취향을 받고 내부 상품 ID·근거를 반환하는 모델 호출 모듈 | 같은 제공사의 호환 모델은 설정 변경. 다른 제공사는 연동 모듈 추가 | 지원 기능·응답 형식·품질·지연·단가·토큰 계산·예산 예약 |
| 메일 | 수신자·제목·본문·발송 결과를 처리하는 발송 모듈 | 발송 모듈·자격 증명·DNS 인증 변경 | 발신자·실제 수신·실패 및 결과 불명·중복 발송·제한 |
| 인증번호 | 발급·목적·귀속·만료·검증·소비 | 발송 업체 변경과 분리 | 인증번호 계약·기존 진행 중 거래·목적 분리 유지 |

초기 구현은 Gemini와 Resend 각 1개 제공사만 지원한다. 교체 검증에는 모의 연동 모듈을 사용할 수 있으며 다른 유료 제공사 계정을 미리 만들 필요는 없다. 운영 요청이 임의의 제공사 주소·모델·자격 증명을 지정하지 못하게 하고 허용한 서버 설정으로만 선택한다.

프론트에는 제공사 고유 응답·오류 객체를 노출하지 않는다. 기존 추천·로그인 계약은 유지하고 새 기능은 공통 요청·응답으로 설계한다. 데이터 보존·품질·비용 조건이 다른 제공사로 자동 전환하지 않으며, 설정 변경도 호환성 검증과 환경 반영을 거친다. 메일 업체를 바꿔도 발신 주소를 유지할 수 있으나 새 업체의 DNS 인증은 다시 수행해야 한다.

## 6. 환경변수 계약

이름은 후속 DEV가 구현하고 QA_DEVOPS가 환경별 주입·검증할 계약이다. 현재 `.env.example`·application·Compose가 아래 변수를 지원한다고 가정하지 않는다.

| 이름 | 용도 | 로컬 계획값 | 운영 계획값 |
|---|---|---|---|
| `AI_PROVIDER` | 모델 연동 선택 | `gemini` | `gemini` |
| `AI_MODEL` | 허용 모델 | `gemini-4-hydrogen` | `gemini-4-hydrogen` |
| `GEMINI_API_KEY` | Gemini 인증 | 환경별 비밀 주입 | 환경별 비밀 주입 |
| `AI_MONTHLY_BUDGET_USD` | 앱 월 AI 한도 | `8` | `8` |
| `MAIL_PROVIDER` | 메일 연동 선택 | `resend` | `resend` |
| `RESEND_API_KEY` | 메일 발송 인증 | 발송 전용 비밀 주입 | 발송 전용 비밀 주입 |
| `MAIL_FROM` | 발신 주소 | `CoffeeProd <no-reply@mailsender.ttagyulab.com>` | 동일 |
| `OAUTH_GOOGLE_CLIENT_ID` | Google 웹 클라이언트 식별 | 로컬 등록 클라이언트 | 운영 등록 클라이언트 |
| `OAUTH_GOOGLE_CLIENT_SECRET` | Google 백엔드 인증 | 환경별 비밀 주입 | 환경별 비밀 주입 |
| `OAUTH_KAKAO_CLIENT_ID` | 카카오 REST API 키 | 로컬 등록 앱 키 | 운영 등록 앱 키 |
| `OAUTH_KAKAO_CLIENT_SECRET` | 카카오 백엔드 인증 | 환경별 비밀 주입 | 환경별 비밀 주입 |
| `APP_BACKEND_URL` | 콜백 기준 주소 | `http://localhost:8080` | `https://api-coffeeprod.ttagyulab.com` |
| `APP_FRONTEND_URL` | 허용 프론트 기준 주소 | `http://localhost:3000` | `https://coffeeprod.ttagyulab.com` |

모든 비밀값은 백엔드 전용으로 주입하며 `NEXT_PUBLIC_*`·프론트 번들·Git·문서에 넣지 않는다. 로컬 환경과 테스트는 먼저 모의 제공사로 실행하고 실제 연동은 준비 확인 후 명시적으로 수행한다. 실제 로컬 호출도 운영과 같은 프로젝트·계정이면 AI 예산·메일 제공량을 공유한다. 개발·운영 앱을 나눌 경우 각 자격 증명의 콜백·계정·비용 범위를 따로 확인한다.

DEV는 필요한 설정·환경변수 예시·Compose 전달을 구현하고 누락·잘못된 설정의 동작을 문서화한다. PM이 제품 설정 파일을 미리 변경하지 않는다.

## 7. 인계·검증 기준

| 업무 | 반영할 기준 |
|---|---|
| DEV-OAUTH-001 | 전체 콜백·동의 항목, 검증되지 않은 이메일의 가입 보완, 공통 메일 인증 목적 분리, 기존 계정 명시적 연결 |
| DEV-PASSWORD-RESET-001 | 공통 인증 컴포넌트와 Resend 발송 모듈 분리, 위 인증번호·발송 제한, 가입 보완과 코드·권한 혼용 방지 |
| DEV-AI-RECOMMEND-001 | 선정 모델·후보 및 출력 제한, 예약·정산·한도, 모듈 교체와 설정 계약 |
| QA-OAUTH-001 | 실제 제공사·콜백·이메일 누락 및 미인증·중복, 다른 인증 목적 코드 거부 |
| QA-PASSWORD-RESET-001 | 실제 수신·DNS 인증, 경계값·만료·재사용·재발송과 동시성·목적 분리·제공사 교체 후 계약 유지 |
| QA-AI-RECOMMEND-001 | 비용 예약·동시 요청·결과 불명·한도·출력 불완전·장애, 모의 교체 후 공통 계약·기존 추천 유지 |

공통 인증 컴포넌트는 DEV-PASSWORD-RESET-001에서 먼저 구현·자체 검증해 DEV-OAUTH-001의 가입 보완에 인계한다. 두 작업의 계정 계약 조사·제공사 인증 구현은 병행할 수 있으며 서로의 전체 완료를 선행 조건으로 걸지 않는다. 실제 메일이 필요한 OAuth 가입 보완 검증은 메일 환경 준비 후 수행한다.

제공사 교체 검증은 대체 모의 모듈로 같은 입력·응답·오류 계약을 검사한다. 모델명만 바꾼 경우에도 후보 제한·상품 정보·토큰 상한·비용 정책과 한국어 취향 결과를 재검증한다. 실제 OAuth·수신·AI 품질은 모의 통과로 대체하지 않는다.

PM-INTEGRATION-001의 완료 범위는 사용자 승인 정책·설정 준비 목록·후속 업무 반영·문서 정합성이다. 외부 가입·키 설정·결제·DNS 변경·실제 발송 및 로그인·모델 품질·제품 구현·배포는 이번 작업에서 수행하지 않는다. 구현·검증된 기능이 없으므로 FEATURES.md에 새 기능을 완료로 등록하지 않는다.

## 8. 출처와 확인 범위

공식 문서 확인일은 2026-11-16이다. 가격·제공량·콘솔 기능과 권한은 실제 연동 준비 시 다시 확인한다.

- Google: 모델·추론·요금·프로젝트 비용 제한, Google OIDC·웹 OAuth 공식 문서.
- Resend: Free 요금표·도메인 및 Cloudflare DNS·메일 API 공식 문서.
- 카카오: 로그인 설정·동의 항목·REST API 공식 문서.
- OWASP: 비밀번호 복구 설계 참고. 이 문서의 제한 수치를 OWASP 권장값이라고 표현하지 않는다.
- 현재 환경: 저장소 인증·추천·배포 설정과 공개 프론트의 API 기준 주소를 조사했다. 콘솔 권한·실제 자격 증명·청구 상태·DNS 인증·제품 연동 성공은 확인하지 않았다.
