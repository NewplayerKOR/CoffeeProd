# 회원 전용 자연어 커피 추천

DEV-AI-RECOMMEND-001 / 2026-11-17. 기존 비회원 선택형 POST `/api/v1/coffee-recommendations`와 회원 저장 취향 GET `/api/v1/coffee-recommendations/me` 계약은 유지한다.

## 화면·API

`/recommendations` 상단에 자연어 입력을 제공한다. 활성 회원이 Bearer JWT로 POST `/api/v1/coffee-recommendations/ai`를 호출한다. 비회원은 로그인 안내와 기존 취향 조건을 이용한다. 입력은 메모리에서만 관리하며 URL·브라우저 저장소에 남기지 않는다. 프론트는 요청 중 중복 제출을 막고 자동 재시도하지 않는다.

요청: `{"preference":"산미가 적고 고소한 커피를 우유와 마시고 싶어요"}`. 공백 제외 1~1,000자. 응답은 기존 CommonResponse이며 `data`는 최대 5개 배열이다.

```json
{"productId":17,"name":"상품 DB 이름","price":12000,"stockQuantity":3,"weightGrams":200,"href":"/products/17","reasons":["산미 1/5","바디 5/5"]}
```

401/403은 인증·회원 상태, 400은 입력, 404는 후보 없음, 429는 호출 또는 월 예산, 502는 유효하지 않은 결과, 503은 설정·Redis·제공사 오류, 504는 시간 초과다. 오류에는 제공사 원문·키·입력을 넣지 않는다. 화면에 오류와 기존 추천 이동 경로를 함께 제공한다. 성공 응답은 `Cache-Control: no-store`다.

## 후보·정보 보호

DB에서 ON_SALE·재고 > 0·커피 프로필 보유 상품을 ID 오름차순으로 최대 20개 읽는다. 이 후보 선정은 전체 상품의 의미 검색이나 전수 AI 순위와 다르며, 20개 밖 상품은 이번 호출에서 추천하지 않는다. 실제 카탈로그에서 후보 다양성과 한국어 취향 품질은 QA에서 확인한다.

모델에는 입력 취향과 후보의 ID·가격·로스팅·디카페인·산미·바디·단맛·향만 보낸다. 서버 회원 식별자·이메일·이름·주문·상품 설명·이미지·URL은 전송하지 않는다. 직접 입력한 개인정보까지 자동 제거한다고 보장하지 않으며 입력란에서 개인정보 입력 금지를 안내한다.

시스템 지시와 사용자 JSON을 분리하고 입력을 명령으로 신뢰하지 않는다. 도구·검색·캐시·다른 모델 자동 전환을 사용하지 않는다. 모델은 ID와 허용 속성(ROAST/DECAF/ACIDITY/BODY/SWEETNESS/AROMA/PRICE)을 고른다. 자유 형식 설명·링크는 받지 않는다. 서버가 속성명을 DB 사실 문장으로 바꾸므로 이유는 모델이 고른 추천 속성이다. “우유와 반드시 어울린다” 등 검증할 수 없는 문장을 만들지 않는다.

후보 외 ID·중복·잘못된 형식·속성·5개 초과·빈 결과·불완전 응답을 거부한다. 외부 호출 중 DB 트랜잭션을 유지하지 않고, 응답 직전 새 트랜잭션에서 판매·재고·회원 상태를 다시 읽는다. 품절·판매 중지·삭제 상품을 배제하고 이름·가격·재고·링크는 최신 DB로 구성한다. 구매 시 재고 확보를 보장하지 않는다.

## 모델·시간·토큰

기본 `AI_PROVIDER=gemini`, `AI_MODEL=gemini-4-hydrogen`, 추론 low(GenerateContent REST의 `LOW`)다. `AiModel` 공통 인터페이스로 연동을 분리한다. 호환 설정 변경은 명시적으로 허용한 `gemini-3.8-flash`만 추가 지원한다. 다른 제공사는 인터페이스 구현과 공통 계약 검증을 추가해야 한다. 공개 요청에서 제공사·주소·모델을 선택할 수 없다. 실제 품질과 계정 접근은 각 모델별 별도 검증이 필요하다.

Gemini 고정 HTTPS 주소의 `countTokens`에 동일한 시스템·입력·스키마를 보내 전체 입력 6,000 이하인지 확인한 뒤 생성한다. 자유 형식 상품 설명은 처음부터 제외한다. 입력 토큰을 초과하면 생성하지 않고 내용을 줄이도록 안내한다. `maxOutputTokens=2048`로 추론 포함 출력을 제한한다. count+generate 및 본문 수신에 총 15초를 적용하고 자동 재시도하지 않는다. 응답 본문은 128KiB로 제한한다.

공식 자료 확인(2026-11-17): [모델 및 두 API 지원](https://aistudio.google.com/docs/whats-new-gemini-4-hydrogen), [GenerateContent REST](https://aistudio.google.com/api-reference/generate-content), [토큰 계산](https://aistudio.google.com/docs/tokens), [단가](https://aistudio.google.com/docs/pricing#gemini-4-hydrogen).

## 제한·예산·저장소

회원 연속 60초 2회·UTC 하루 20회, 전체 UTC 하루 100회, UTC 월 $8. 한도는 낮출 수 있고 $8 초과 또는 잘못된 설정은 AI 비활성으로 처리한다. 월 예산은 제공사 프로젝트 청구 상한이나 세금 포함 결제액이 아닌 앱의 토큰 예상 비용 한도다. 같은 프로젝트의 다른 앱 호출은 이 Redis 한도 밖이므로 전용 프로젝트와 비용 알림을 준비한다.

1단위=$0.000000001 정수로 계산한다. Hydrogen은 입력 100만 토큰당 $1.50, 추론 포함 출력 $7.50이다. 6,000/2,048 최대 비용 $0.02436을 호출 전에 예약한다. 모든 요청이 최대를 쓰면 월 328회이고 나머지 $0.00992로 새 요청을 시작하지 않는다. Flash는 공식 2026년 할인 단가 입력 $0.75/출력 $3.75, 2027-01-01부터 $1.50/$7.50을 반영한다. 가격 인상 경계 15초 전부터는 새 단가로 보수적으로 예약·정산한다. 모델 설정을 바꿔도 공통 월 원장을 사용한다.

Redis TIME으로 UTC 일·월 키를 정하고 한 Lua 연산에서 분·일 횟수와 최대 비용을 예약한다. UTC 자정 중 날짜가 바뀌면 실패 처리한다. 같은 회원·다른 회원의 동시 예약에서도 한도를 넘지 않는다. 예약별 모델 단가를 보존하고 정상 usage의 입력+출력+추론 합계를 확인한 뒤 실제 토큰 비용으로 일회 정산한다. 불완전 결과도 유효한 사용량이 있으면 정산하되 상품 결과는 거부한다.

사용량 누락·상한 초과·불일치·과금 불명·시간 초과·제공사 실패는 최대 예약을 유지한다. 동일 요청을 다시 보내거나 예약을 자동 환급하지 않는다. Redis 예약·정산 장애에서는 오류를 반환한다. 정산 실패 시 예약을 보존한다. 호출 횟수는 실패해도 되돌리지 않는다. 월 원장·예약은 다음 달 시작 2일 후까지 보존한다.

이 한도는 신뢰할 수 있는 단일 Redis 원장에 의존한다. 운영 Compose의 AOF를 유지하고 eviction 없이 비용 키를 보존해야 한다. Redis 데이터를 지우거나 별도 Redis로 교체하면 월 사용량을 알 수 없으므로 AI를 끄고 원장을 복구한 뒤 재개한다. 코드가 데이터 삭제나 다른 인스턴스 사용을 감지한다고 보장하지 않는다. 이번 작업은 운영 Redis 설정·복구 절차의 수락을 포함하지 않는다.

## 설정·준비·검증

`.env.example`과 `docker-compose.prod.yml`에 다음을 반영한다. 로컬 Compose는 DB·Redis만 실행하므로 로컬 Java 프로세스에 직접 주입한다.

| 변수 | 기본값·역할 |
|---|---|
| AI_PROVIDER | gemini |
| AI_MODEL | gemini-4-hydrogen |
| GEMINI_API_KEY | 서버 전용 비밀. 누락 시 AI 503, 기존 추천 유지 |
| AI_MONTHLY_BUDGET_USD | 8. 양수·최대 8·소수 9자리 이내 |

사용자는 전용 Gemini 프로젝트·모델 접근·API 키·유료 계정 사용 조건·예산을 준비한다. QA_DEVOPS가 비밀 저장소와 배포 환경에 주입하고 실제 한국어 취향·응답 지연·사용량·청구를 확인한다. 키는 Git·문서·채팅·NEXT_PUBLIC 변수에 넣지 않는다. 무료/유료 데이터 이용 조건도 실제 계정 기준으로 확인한다.

개발 검증은 모의 AiModel, 로컬 모의 Gemini HTTP, 격리 PostgreSQL 16·Redis 7, 실제 Next 렌더링과 모의 API로 수행한다. 실제 Gemini 호출·추천 품질·계정 청구·배포·운영 검증과 독립 QA는 미실행이다. 상세 명령·리비전·집계·증거는 DEV 작업 기록과 PR에 남긴다.
